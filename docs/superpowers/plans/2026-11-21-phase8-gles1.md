# Phase 8: the GLES 1.1 fixed-function pipeline

**Spec:** `docs/superpowers/specs/2026-11-21-gles1-fixed-pipeline-design.md`. Read it first;
this plan does not repeat its reasoning. Background: Phase 5's plan
(`2026-09-16-phase5-gles.md`) for the host-call shape and `2026-09-17-phase7a-native-surface.md`
for the append-only index rule.

**Goal:** host-call indices 492-578 (the 87 `libGLESv1_CM.so` rows of
`core/src/gen/hostcalls.inc`) stop being "unimplemented host call, return 0" and forward to the
device's real `libGLESv1_CM.so` with bounds-checked pointers. Zombie Road Trip and Punch Quest
render their first screen.

**Branch:** `codex/phase4d-launcher` (or its successor). Do not push without being asked.

**Working rules:** ASCII files only; TDD by observing RED first; one commit per task; never
stage `third_party/dynarmic`, `cc`, `cod`, screenshots or APKs.

**Build and test commands.** This checkout has no host C++ toolchain, so the host suite cannot
run here; the Android build is the compile gate and the emulator is the functional gate.

## Task 1: the index range and its name table

**Files:** `core/include/zb/gles1_hostcalls.h` (new), `tools/check_gles1_hostcalls.py` (new),
`tests/host/CMakeLists.txt`.

**Do:**
1. Write `gles1_hostcalls.h` by hand: `kGl1HostCallFirst = 492`, `kGl1HostCallLast = 578`,
   a 87-entry `Gl1HostCallInfo { std::uint32_t index; const char* name; }` table in index
   order, `gl1_host_call(index)`, `gl1_host_call_name(index)` and `is_gl1_host_call(index)`,
   all `constexpr`, in the style of the generated `gl_hostcalls.h`.
2. The checker verifies the table against `core/src/gen/hostcalls.inc` and the NDK header:
   87 rows, indices contiguous 492-578, names identical to the `libGLESv1_CM.so` rows, every
   name declared in `GLES/gl.h`, and no name declared in `GLES2/gl2.h`. NDK discovery copies
   `gen_stubs.py` (`NDK`, `NDK_HOST`).
3. Register the checker as ctest `gles1_hostcalls_check`, next to `gen_gles_check`.

**Tests:** run the checker; it must pass. Break one name deliberately to observe it fail, then
restore.

**Commit:** `gles1: index range and name table for the GLES 1.1 entry points`.

## Task 2: the seam and the 50 pointerless calls

**Files:** `core/include/zb/gl1_backend.h` (new), `core/include/zb/host_gl.h`,
`core/src/gl/host_gl.cpp`, `core/src/gl/host_gl1.cpp` (new), `tests/host/mock_gles1.{h,cpp}`
(new), `tests/host/gles1_marshal_test.cpp` (new), `tests/host/CMakeLists.txt`,
`core/src/jni/proxy_runtime.cpp`, `core/include/zb/proxy_runtime.h`.

**Do:**
1. `Gl1Backend`: 87 virtuals with the NDK signatures, using the `zb::` GL scalar types and
   `GLfixed`/`GLclampx` (`std::int32_t`) declared in this header; every default body calls
   `invoke(name, {gl_backend_word(...), ...})`. No `set_error` (see the spec).
2. `HostGl`: `set_gl1_backend(Gl1Backend*)`, a `Gl1Backend*` member defaulting to null, and
   `bool dispatch_gl1(Call&)` declared privately. `handle_host_call` accepts
   `is_gl1_host_call(index)` as well, uses one name helper that covers both ranges, counts GL1
   calls in the census (slot limit 512 -> 640), and calls `dispatch_gl1` instead of the
   generated `dispatch` for that range. `handle_fast_host_call` stays ES2-only.
3. `dispatch_gl1` in `core/src/gl/host_gl1.cpp`: a `switch` over the 87 indices. This task
   implements the 50 pointerless ones; every other index is a "not implemented yet" rejection
   that names the function, so Task 3 cannot forget one silently.
4. A missing backend rejects once (`GL_INVALID_OPERATION`, logged), never aborts.
5. `MockGles1` records name plus arguments and the raw pointer words, like `MockGles`.
6. `GuestJniEngine`: append `Gl1Backend* gl1_backend = nullptr` to the constructor, pass it to
   `set_gl1_backend`, and add `fill_range(kGl1HostCallFirst, kGl1HostCallLast,
   HostCallTarget::Gl)` to the dispatch table. The Android backend arrives in Task 4.

**Tests:** `gles1_marshal_test` dispatches all 50 pointerless names with recognizable words and
asserts the recorded arguments (float bit patterns, fixed-point pass-through, `GLubyte`
truncation for `glColor4ub`, six arguments for `glOrthof`/`glFrustumf` read from the guest
stack), plus the missing-backend rejection.

**Commit:** `gles1: the seam, the dispatcher, and the pointerless calls`.

## Task 3: pointer marshaling, pname sizes and client arrays

**Files:** `core/src/gl/host_gl1.cpp`, `core/src/gl/gl_manual.cpp`,
`tests/host/gles1_marshal_test.cpp`.

**Do:**
1. `gl1_pname_count(GLenum)` implementing the spec's table, with the per-function overrides and
   a driver query for `GL_COMPRESSED_TEXTURE_FORMATS`.
2. Extend `gl_pname_count` in `gl_manual.cpp` with the ES1 result sizes, so the shared
   `glGetFloatv`/`glGetIntegerv`/`glGetBooleanv` handlers validate the whole output.
3. The 16 pointer-taking functions: validate through `Call::pointer<T>(position, elements, need)`
   (read for inputs, read|write for outputs). No copies.
4. The five client-array functions: validate one byte readable, hand the host pointer to the
   driver, remember the 32-bit guest address per array in a thread-local shadow keyed by EGL
   generation.
5. `glGetPointerv`: for the five array pnames, write the remembered guest address into the
   validated 4-byte output and do not call the driver; any other pname is rejected with
   `GL_INVALID_ENUM`.
6. Record `gl-context: <GL_VERSION>` once, on the first GL1 call, through
   `RuntimeReport::note_gl_detail`.

**Tests:** extend `gles1_marshal_test` with one case per pointer rule: a 16-float matrix, a
4-element clip plane, each pname-sized input and output, an out-of-range pointer, an unmapped
page, a read-only page as an output, the client-array round trip through `glGetPointerv`, and
`glGetFloatv(GL_MODELVIEW_MATRIX)` asking for 16 elements.

**Commit:** `gles1: pointer marshaling, pname sizes, client arrays and glGetPointerv`.

## Task 6: keep the GL visibility diagnostics off an OpenGL ES 1.1 context

Found by Task 5's Punch Quest run: `SIGSEGV` at address 0 inside the driver, called from
`gl_diagnostics.cpp`'s `sample()` as `glCheckFramebufferStatus(GL_FRAMEBUFFER)`. Zombie Road Trip
reproduced it at the identical pc once `diagnostics=true`, so it is the diagnostics, not the
guest. The A/B that proved it: Punch Quest with `diagnostics=false` ran 28,520 GL calls and
rendered, then crashed after 82 calls with it on.

**Files:** `core/src/gl/gl_diagnostics.cpp`, `tests/host/gles1_marshal_test.cpp`,
`tests/host/gles_marshal_test.cpp`, `tests/host/gl_chain_test.cpp`.

**Do:**
1. Cache the context profile per `GlBackend` (`profile_backend`, `profile_known`,
   `profile_gles2plus`), decided from `glGetString(GL_VERSION)`: `OpenGL ES 2` / `OpenGL ES 3`
   prefixes run the diagnostics, anything else skips them.
2. Early-out of `gl_diagnose`, `gl_diagnose_before` and `gl_diagnose_swap` for a legacy profile,
   and of `gl_diagnose_map` / `gl_diagnose_map_collision`, which also query the driver.
3. Record `gl-diagnostics: <GL_VERSION> profile skip` (or ` profile on`) once, so a report with
   no visibility lines says why.
4. Do not cache a null `GL_VERSION`: that means no current context yet, not a legacy one.
5. Existing diagnostics tests must declare a modern `GL_VERSION` on their mock backend.

**Tests:** `gles1_marshal_test` enables diagnostics on an `OpenGL ES-CM 1.1` mock and asserts a
draw reaches only `glGetString` + `glDrawArrays`, that no `gl-sample-draw-*`, `gl-draws:` or
`gl-first-draw-call:` line appears, and that the skip line does.

**Commit:** `gles1: run the GL visibility diagnostics only on an ES 2.0+ context`.
